# RAGFlow 选型评估（R 层）

> 版本：v0.27.2（commit `a024bea`）｜场景：**私有化交付给央国企客户**，约束：**信创国产化、内网离线部署**
> 证据明细（License 逐包、安全配置逐项、信创与离线逐点）见 `06a-证据明细-License安全信创离线.md`；本文是结论和关键证据。
> 标记：✅ 代码事实 · 🔍 推断 · ❓ 未确认

## 结论：有条件推荐

可以作为知识库项目的**检索问答底座**，前提是满足下面三个条件：

1. **按项目预留权限、审计、信创的二次开发包**（粗估 2–4 人月 🔍），或者与官方洽谈企业版授权。开源版的 RBAC、审计日志、敏感词都是空壳。
2. **交付前做一轮合规与安全整改**：移除 GPL 依赖 extract-msg、把文档引擎从 Elasticsearch 换成 OpenSearch / Infinity / OceanBase、替换仓库自带的 RSA 私钥和全部默认口令。
3. **锁定版本，自建升级回归**：项目仍是 0.x，正从 Python 向 Go 迁移，1.0 将至，版本间有破坏性变更。

主要理由：
- **功能底座强**：解析、检索、问答、Agent、开放接口这几块在 28 条示例需求中直接满足 10 条、部分满足 12 条，且都有代码证据（见 `07-需求响应矩阵.md`）。
- **协议和社区都健康**：标准 Apache-2.0，社区大、贡献者分散、发版频繁。
- **企业级能力是短板**：权限、审计、信创正好是央国企验收最看重的部分，开源版都要补。

## 1. 功能匹配度

| 维度 | 判断 | 依据 |
|---|---|---|
| 文档解析与知识加工 | 强 | 14 种领域切片方法、版面/表格/OCR 识别、切片人工干预、知识编译（实验性）。见 `01-业务全景.md` 第 3 节 |
| 检索问答 | 强 | 混合检索 + 重排 + 元数据过滤，答案带引用可回溯原文 |
| 应用编排 | 强 | Agent 画布 56 类节点、19 个模板、Webhook、版本发布 |
| 开放集成 | 强 | HTTP API、Python SDK、OpenAI 兼容接口、MCP Server、嵌入组件、IM 机器人 |
| 权限与安全 | **弱** | 只有「仅自己 / 团队」两档共享；RBAC、审计、敏感词为企业版 |
| 运维与可观测 | 中 | 服务状态有；监控大盘、用量统计界面为企业版或缺失 |

示例需求清单（28 条）的响应：满足 10、部分满足 12、仅企业版满足 3、需二次开发 1、待验证 2。

> ⚠️ 注意 v0.27.0 起 **GraphRAG 和 RAPTOR 已废弃**，由「知识编译」的 Graph、Tree 取代 ✅ [docs/release_notes.md:L95](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/docs/release_notes.md#L95)。网上很多介绍 RAGFlow 的文章仍以这两项作为卖点，写方案时不要沿用。

## 2. License

**根协议**：✅ 标准 Apache-2.0，与标准文本比对无附加条款 [LICENSE:L1-L201](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/LICENSE#L1-L201)。没有 Dify、FastGPT 那类「限制多租户 SaaS、禁止去 Logo」的附加条件，可以换 Logo 白标；但不能使用 RAGFlow 商标销售。

**存在闭源企业版**：✅ 31 个 `*_ee.go` 占位文件，开源版里角色权限、审计日志、敏感词、License 校验、监控大盘、部分 SSO 通道（飞书、Azure、工行）都返回 not supported [internal/admin/service_ee.go:L37-L46](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/internal/admin/service_ee.go#L37-L46)。官方 FAQ 也说明企业版的 DeepDoc 模型用专有数据训练 [docs/faq.mdx:L73](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/docs/faq.mdx#L73)。这不是协议风险，而是**开源版能力边界**。

**依赖中需要处理的**：

| 项 | 风险 | 建议 |
|---|---|---|
| extract-msg（解析 Outlook .msg），🔍 GPL-3.0，进程内 import | 私有化分发时可能被认定整体受 GPL 约束 | 移除依赖、禁用 .msg 解析，或拆成独立服务 ✅ [pyproject.toml:L43](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/pyproject.toml#L43) |
| 默认文档引擎 Elasticsearch 8.11，🔍 只能在 SSPL / ELv2 中二选一 | 交付给客户使用一般可行，但条款复杂，且不利于后续 SaaS 化 | 换成 OpenSearch（Apache-2.0）、Infinity 或 OceanBase ✅ [docker/.env:L41](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/docker/.env#L41) |
| 镜像内 ghostscript（🔍 AGPL）、pandoc（🔍 GPL）、微软 ODBC 驱动（专有 EULA） | 再分发镜像即分发这些二进制 | 提供源码获取方式或移除；核对微软再分发条款 ✅ [Dockerfile:L54](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/Dockerfile#L54)、[L162-L165](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/Dockerfile#L162-L165) |
| 无 NOTICE / 第三方声明汇总 | Apache-2.0 要求保留声明 | 交付方自行整理第三方组件清单 |

前端依赖全部为宽松协议 ✅（package-lock 自带协议字段）。Python 依赖协议需逐包复核（uv.lock 无协议字段）。

**按使用方式**：

| 方式 | 结论 |
|---|---|
| 内部使用 | ✅ 可以 |
| **私有化交付（本场景）** | ✅ 可以，需完成上表整改 |
| SaaS 多租户 | ⚠️ 有条件：必须换掉 ES；开源版缺配额、计费、RBAC |
| 二次销售（OEM） | ⚠️ 可以：允许闭源修改后销售，不得用 RAGFlow 商标；与官方企业版存在商务竞争 |

## 4. 安全（交付前必须整改）

1. **仓库自带 RSA 私钥**，所有部署共用，前端"密码加密"等同混淆 ✅ [conf/private.pem:L1](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/conf/private.pem#L1)。→ 重新生成密钥对，强制 HTTPS。
2. **默认口令统一且管理员口令已预设** ✅ [docker/.env:L247](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/docker/.env#L247)。→ 全部改掉。
3. **开放注册默认开启** ✅ [docker/.env:L343-L344](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/docker/.env#L343-L344)。→ 关闭。
4. **中间件端口默认映射到宿主机**（MySQL、MinIO、Redis、ES）✅ [docker/docker-compose-base.yml:L235](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/docker/docker-compose-base.yml#L235)。→ 只暴露 Nginx。
5. **代码沙箱管理容器以 privileged 运行并挂载 docker.sock** ✅ [docker/docker-compose-base.yml:L183-L207](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/docker/docker-compose-base.yml#L183-L207)。执行容器本身隔离较好（gVisor、只读、无网络）。→ 不需要代码节点就不启用 sandbox profile。
6. **API Key 等于整个租户权限**，无细分范围 🔍。→ 对外集成时在网关层加限制。

## 5. 部署、信创与离线

**部署成本**：官方最低 4 核 / 16 GB / 50 GB ✅ [README_zh.md:L151-L154](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/README_zh.md#L151-L154)，最少 5 个容器（应用、文档引擎、MySQL、对象存储、Redis）。另需单独部署大模型和向量模型推理服务，**这部分通常才是硬件大头**（GPU）。有 Helm chart，但版本 0.1.x，只覆盖 Python 后端。

**信创**：

| 项 | 现状 | 补齐难度 |
|---|---|---|
| x86 国产 CPU（海光） | 🔍 可直接用官方镜像，需实测 | S |
| ARM 国产 CPU（鲲鹏、飞腾） | ✅ 官方不出 ARM 镜像 [docs/faq.mdx:L93](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/docs/faq.mdx#L93)；Dockerfile 有 aarch64 分支可自建，但 Go 原生库只有 x64 | M（Python 后端自建镜像）；Go 后端与 Infinity ❓ |
| 国产操作系统（麒麟、统信） | ✅ 未找到适配；OpenCloudOS 9 方案已失效且用个人镜像 | S–M，需实测 |
| 国产数据库 | ✅ GaussDB、OceanBase 已支持（元数据库 + 文档引擎）[api/db/db_models.py:L797-L803](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/api/db/db_models.py#L797-L803)；达梦、人大金仓未支持 | 金仓 S–M（试 PG 兼容）；达梦 L |
| 国产 AI 芯片 | ✅ 版面识别有昇腾分支 [deepdoc/parser/pdf_parser.py:L75-L89](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/deepdoc/parser/pdf_parser.py#L75-L89)；其余模型走 ONNX（CPU 即可） | 大模型推理侧另行选型 |
| 国密 | ✅ 可选 SM4 存储加密 [common/crypto_utils.py:L208-L244](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/common/crypto_utils.py#L208-L244) | 传输层国密需另配 |

**内网离线**：解析模型、nltk、tika 已打进镜像 ✅ [Dockerfile:L17-L30](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/Dockerfile#L17-L30)，本地模型服务支持 Ollama、vLLM、Xinference、OpenAI 兼容接口等，核心链路 🔍 可离线运行。需注意：
- 镜像默认 `HF_ENDPOINT` 指向外部镜像站 ✅ [Dockerfile:L296](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/Dockerfile#L296)，内网应清空；
- 浏览器组件、联网搜索等 Agent 工具在内网不可用，需在模板中屏蔽；
- `DEVICE=gpu` 会在运行时 pip 安装 torch ✅（见 `02-技术架构.md` 第 8 节），离线 GPU 部署需自建镜像；
- 官方只有一段 `docker save / load` 说明，**没有完整离线部署指南** ✅ [docs/administrator/upgrade_ragflow.mdx:L92-L102](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/docs/administrator/upgrade_ragflow.mdx#L92-L102)；
- 是否完全无外联 ❓：建议断网环境端到端冒烟 + 抓包。

## 6. 替代方案

| 项目 | 协议 | 与 RAGFlow 的差异 |
|---|---|---|
| Dify | 🔍 Apache-2.0 + 附加条件（限制多租户 SaaS、不得去除 Logo）[OSI 邮件列表讨论](https://lists.opensource.org/pipermail/license-discuss_lists.opensource.org/2025-October/022423.html) | 应用编排与生态更强，文档深度解析弱于 RAGFlow；协议对白标和 SaaS 有限制 |
| FastGPT | 🔍 Apache-2.0 + 附加条件（未经授权不得做多租户 SaaS，不得改 Logo 和版权）[官方协议说明](https://doc.fastgpt.io/en/introduction/opensource/license) | 国内团队，工作流易用；协议限制与 Dify 类似 |
| MaxKB（1Panel 团队） | 🔍 GPL-3.0 [项目介绍](https://dev.co/ai/frameworks/maxkb) | 轻量、上手快，国内私有化案例多；GPL 对闭源二次销售不友好 |
| WeKnora（腾讯） | 🔍 MIT [GitHub](https://github.com/Tencent/WeKnora) | 协议最宽松，向量库可选 pgvector、Milvus、Qdrant 等；成熟度与社区规模不及 RAGFlow，需单独评估 |

> 以上替代方案信息来自网络检索（2026-10-12），未做代码级核对；如需正式对比，用 repo-dissect 的多项目对比模式逐个拆解。
