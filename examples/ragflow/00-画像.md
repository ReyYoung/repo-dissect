## 1. 一句话定位与项目类型

- **定位**：基于"深度文档理解"的开源 RAG 引擎和智能体平台，面向需要从复杂格式文档里做可溯源问答的企业。✅ [pyproject.toml:L3-L4](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/pyproject.toml#L3-L4)
- **项目类型**：**应用型产品**。有 Web 工作台、管理后台、HTTP API、SDK 和 MCP Server，业务全景层（L1）做完整版。
- **AI 形态**：**混合型，嵌入型为主**。主链路是"上传 → 解析切片 → 向量化 → 检索 → 拼提示词交给模型回答"，每一步做什么由代码决定（问答入口 `async_chat` ✅ [dialog_service.py:L594](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/api/db/services/dialog_service.py#L594)）。次形态是画布里的 Agent 组件：模型返回工具调用 → 执行 → 结果回填 → 再调模型，默认最多 5 轮 ✅ [agent_with_tools.py:L69](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/agent/component/agent_with_tools.py#L69)、[chat_model.py:L636-L643](https://github.com/infiniflow/ragflow/blob/a024bea0cd93f39e6652a42bf84dd20c55bc560b/rag/llm/chat_model.py#L636-L643)。主形态的 AI 链路表见 `02-技术架构.md`。

## 7. 结论：值得深挖

1. **生态和活跃度在同类里领先**：社区大、贡献者分散、发版频繁，长期维护风险低。
2. **协议本身友好**：标准 Apache-2.0，允许闭源修改和私有化交付。
3. **但有两个必须查清的风险**：开源版的权限、审计等企业级能力被裁剪；项目正从 Python 向 Go 迁移、即将进入 1.0，接口和数据结构变动剧烈。
